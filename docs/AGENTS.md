# Documentation instructions

Use [README.md](README.md) as the documentation map. Root instructions still
apply. Keep user controls, architecture, research evidence and current status
distinct so another agent can find the right level of detail quickly.

- Check source, tests and original evidence before claiming implemented
  behavior. Clearly mark provisional interpretations and unavailable references.
- Preserve original function addresses, resource IDs, numeric units and known
  quirks in research notes. Separate community divergences from original rules.
- Do not fabricate missing Bible, reference-image, ResForge or decompile files.
  These local research assets are intentionally excluded from the public repo.
- Use relative Markdown links inside repository docs; verify new links resolve.
  Keep machine-specific paths in the handoff's explicitly local-workspace section.
- Treat test reports as dated evidence. Do not claim a full campaign, audible
  sound, a successful Ghidra audit or a CI run based on a narrower check.
- Update the index when adding a subsystem guide. Keep agent instructions brief
  and actionable; deeper explanations belong in the linked guide.
- Preserve the unofficial community identity, AI tooling disclosure and credits.
  Use regular version numbers and the shared public release/update process.

Documentation-only changes do not need a C++ rebuild. Validate links and any
commands or embedded workflow/script examples affected by the change.
